# Lumior MBA Skills

把一个模糊的管理兴趣，逐步变成有研究对象、有证据、有数据来源的 MBA 研究问题。

这是一套中文论文研究指导 Skill：选题 → 读文献与收窄 → 文献综述 → 开题报告与答辩。每一步留下可编辑的 Markdown 成果，供下一步继续使用。可独立使用，不需要安装 Lumior，也不需要安装 gstack。

改写自 [Garry Tan 的 gstack](https://github.com/garrytan/gstack)。我们将阶段化追问、前提检查、备选方案、评审与成果交接的思路适配到 MBA 研究。原始上游版本未记录；当前上游只用于核查，不能冒充改写基线。详见 [来源与改动](docs/PROVENANCE.md) 和 [许可声明](NOTICE.md)。本项目不代表 gstack 或 Garry Tan 官方背书。

## 四个 Skill

| Skill | 做什么 | 主要成果 |
| --- | --- | --- |
| `/mba-topic` | 从真实管理事件、研究对象、理论和数据可得性出发，确认研究问题 | `thesis/topic.md` 选题卡与收窄记录 |
| `/mba-lit` | 筛选和阅读用户提供的文献，核对假设，追问与已有研究的差别 | 文献矩阵、文献卡、经确认的选题更新 |
| `/mba-review` | 按概念组织文献，确认主张，再生成或评审综述 | 综述提纲、草稿与评审记录 |
| `/mba-proposal` | 对照学院模板，确认方法、数据和进度，模拟答辩 | 开题提纲、草稿与答辩记录 |

## 适用哪些模型与工具

这套 Skill 是研究流程说明，不绑定某个模型品牌。Claude、GPT、Gemini、Kimi、DeepSeek、Qwen 等模型可以作为候选，但具体版本能否可靠执行，取决于指令遵循、中文研究理解、上下文容量，以及宿主提供的工具；本项目尚未逐一验证这些模型，以上不是兼容认证或效果排名。

需要区分“模型能读懂”与“工具能完整执行”：

| 使用环境 | 可以怎样使用 | 限制 |
| --- | --- | --- |
| Claude Code 风格的文件 Agent | 按下文安装，读取资料并保存阶段成果 | 当前文本按这类工具编写；仍需实际验证所用版本 |
| 其他具备 Skill、文件读写和资料读取能力的 Agent | 适配工具名称、安装路径与提问方式后使用 | 不保证原样安装即可运行；PDF 提取需单独适配 |
| 普通聊天窗口 | 提供完整 Skill 文本和材料，按步骤对话，复制保存成果 | 链接可能无法读取，也未必能持续保存文件；不能据 AI 说“已保存”判断真的落盘 |
| Lumior 内置论文助手 | 使用应用中的论文流程和卡片 | 可选模型由 Lumior 当前配置决定，不由独立仓库决定 |

Skill 格式与宿主能力可参见 [Agent Skills 官方说明](https://github.com/agentskills/agentskills/blob/main/docs/home.mdx) 和 [Claude Skills 文档](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)。

## 一句话开始

复制下面这一句给能读取网页或仓库内容的 AI：

> 请读取 https://github.com/limanman-design/lumior-mba-skills 的 README 和 skills/mba-topic/SKILL.md，按这套流程带我做 MBA 选题，一次只问一个问题；先说明你是否已完整读到 Skill、能否读写当前论文项目文件，不能读取时请让我提供全文，不能保存时请输出可复制的 Markdown，不要宣称已保存。

这句话用于开始使用，不等于自动安装，也不会自动让聊天窗口获得文件权限。无法读取链接时，打开仓库中的 `skills/mba-topic/SKILL.md`，将完整内容复制或作为文件提供给 AI。后续阶段再提供对应 Skill 和此前的选题卡、文献矩阵；不要只给一个仓库链接就假定它已读完全部流程。

## thesis/ 在哪里保存

独立文件 Agent 使用时，`thesis/topic.md`、`thesis/lit-matrix.md` 等是当前论文项目目录中的实际文件，前提是宿主有写入权限且确实执行了文件写入。

Lumior 画板模式沿用这些路径作为逻辑名称：`thesis/topic.md` 对应选题卡，`thesis/lit-matrix.md` 对应文献矩阵卡。运行前从当前卡片构造项目文件快照；修改已有成果先形成待采纳建议，用户接受后再替换卡片并保存历史。相关状态随工作区保存，并不因此在电脑上自动创建一套同名 Markdown 目录。

所以卡片正文中出现 `thesis/topic.md` 是流程的文件命名约定，不是磁盘路径或保存成功凭据。独立仓库的文件与 Lumior 卡片也不会自动双向同步。

## 开始使用

这份版本保留 Claude Code 风格的工具名称与 `/命令`。需要能读写项目文件的 Agent、用户自己的模型服务及可读取的论文材料；没有附带 API Key 或免费额度。尚未完成各宿主的真实端到端认证。

在 Claude Code 中，将 `skills/` 下四个文件夹复制到 `~/.claude/skills/`，保留各文件夹的许可证和声明。不要覆盖已有同名 Skill，先备份旧目录。然后在**专门的论文工作目录**启动 Agent，输入 `/mba-topic`。另一篇论文使用另一个目录，避免共用 `thesis/`。

可先建立 `thesis/`，将 `templates/settings.md` 复制为 `thesis/settings.md`，明确写作模式。默认允许确认后生成初稿；学院限制 AI 代写时，选择“只给提纲和评审”。学院规则和导师要求优先于通用篇数、章节或字数建议。

把有权使用的论文放入 `thesis/refs/`；学院模板放入 `thesis/template/`，评审要求放入 `thesis/rubric/`。不要把自己的论文工作目录提交到公开仓库。

无 `AskUserQuestion` 的宿主可用文字选项作答。其他 Agent 需要适配文件工具、Skill 路径和调用方式；不能把文中的 Claude 安装路径直接视为通用安装路径。PDF 文本提取依赖宿主能力；随包的 `pdftext.swift` 只适用于有 Swift 编译工具的 macOS。Windows/Linux 使用宿主 PDF 工具或先转为带页码的文本；扫描件需 OCR，不能据标题猜内容。

## 为什么这样设计

价值主要在于让“研究决策”持续接受证据检验，而不是一次生成更长的文章：

- **先确认问题再写作**：把“想做绩效优化”拆成对象、具体问题、已有证据和数据约束，减少先有对策、后找论据。
- **读文献必须影响判断**：每篇文献对应假设及支持／反驳／条件，推动更新研究问题，避免只积累摘要。
- **学生说明差别**：同题研究不是失败；要求学生说明情境或机制为何影响结论，保留研究决策的主体性。
- **产物跨阶段衔接**：选题卡、矩阵和版本记录为后续写作提供共同依据，减少长对话中的遗漏和漂移。
- **确认与复核**：缺证据标待补，选题变化先确认，草稿覆盖前备份，生成后按明确条目复核。

这些是可检验的设计机制，不等于已证明提高开题通过率或学习效果。[设计依据、限制和评估方案](docs/DESIGN-AND-EVIDENCE.md) 说明如何判断是否有效。

## 使用边界

“不要编造”是提示约束，不是技术保证。必须回到原文核对文献卡与引用；同一个模型的自查不能代替独立审阅。只追求完成清单可能产生形式合规，过度追问也可能增加负担。约 15 篇文献等数量是经验提示，不是适用于所有学院的门槛。

独立 Skill 会通过宿主文件工具写入项目；Lumior 的画板气泡、待采纳保护、撤销、计费、DOI 补全和自动去重校验不随这个文本包一起提供。自行保留备份并检查变更。资料是否发往模型服务由宿主与所选供应商决定，文件保存在本地不等于完全离线处理。
